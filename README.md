# Мебельная фабрика «Профиль» — панель учёта производства

Веб-панель, которая объединяет два журнала (простои и брак) и показывает директору, **где фабрика теряет время и деньги и что с этим делать**.

Версия 3: **сервер с учётными записями** (SQLite, 4 роли, админ-панель), экран без прокрутки на мониторе 1920×1080 и переработанная читаемость карточек. Версия 2 — дизайн-система **VOLT**, графики **Bklit UI**, движение **motion** и **anime.js**. Версия 1 (чистый JS + Chart.js) сохранена в git-теге `v1.0-sdacha` и ветке `backup/v1-sdacha`.

## Два способа запуска

| | Автономная панель | Сервер с входом по паролю |
|---|---|---|
| Запуск | двойной щелчок по `panel/index.html` | `npm start` (нужен Node.js 22.18+) |
| Данные | вшиты в файл | в базе SQLite на сервере, отдаются только после входа |
| Учётные записи | нет — режим демонстрации, видно всё | 4 роли, права проверяет сервер |
| Для чего | показать и проверить цифры | реальная работа нескольких людей |

## Способ 1. Автономная панель (30 секунд, ничего устанавливать не нужно)

1. Распакуйте архив.
2. Откройте файл **`panel/index.html`** двойным щелчком (или `index.html` в корне — он сам переведёт на панель). Подойдёт любой современный браузер: Chrome, Edge, Firefox, Safari.
3. Панель откроется сразу с данными за 19.05–15.06.2026. Интернет не нужен: библиотеки, шрифты и исходные журналы вшиты в один файл (≈2 МБ).

Если панель опубликована на GitHub Pages — просто откройте ссылку.

## Способ 2. Сервер с учётными записями

```bash
npm start        # http://127.0.0.1:3000 — сторонние библиотеки не нужны
```

Панель для сервера уже собрана (`server/public/index.html`); пересобрать — `npm run build`. База создаётся при первом запуске в `server/data/profil.db` и заполняется журналами из `server/seed.json`.

**Демо-учётки** (создаются при первом запуске, пока `PROFIL_DEMO` не равно 0):

| Логин | Пароль | Роль | Что видит и может |
|---|---|---|---|
| `admin` | `Admin-2026!` | Администратор | всё; вкладка «Администрирование»: пользователи, журнал действий, служебное; правит любые записи |
| `director` | `Director-2026!` | Директор | все листы, деньги и ставки, загрузка файлов, PDF; только просмотр |
| `chief1`, `chief2` | `Chief1-2026!`, `Chief2-2026!` | Начальник цеха | только свой цех, без денег; добавляет и правит свои записи простоев |
| `otk` | `Otk-2026!` | Оператор ОТК | только брак и журнал брака; добавляет и правит свои записи брака |

**Для настоящей работы:** запускать с `PROFIL_DEMO=0` (демо-пароли не создаются) и задать `PROFIL_ADMIN_PASSWORD`; иначе администратор получит случайный пароль, напечатанный в консоли, и при первом входе обязан его сменить. Прочие переменные: `PORT`, `HOST`, `PROFIL_DB`, `PROFIL_SECURE=1` (флаг Secure у cookie — за HTTPS), `PROFIL_TRUST_PROXY=1` (доверять X-Forwarded-For за прокси).

### Как устроена защита

- Пароли — scrypt с индивидуальной солью; не короче 8 символов, не равны логину и не из списка самых частых. Администратор выдаёт временный пароль, человек обязан сменить его при входе.
- Сессия — случайный токен в cookie `HttpOnly; SameSite=Strict`; в базе хранится только его SHA-256. Живёт до 12 часов, закрывается после 2 часов без действий.
- Подбор пароля: 5 неудач подряд блокируют запись на 15 минут (одинаково и для несуществующих логинов), отдельный лимит на IP; по времени ответа нельзя понять, есть ли такой логин.
- Права проверяются на сервере при каждом запросе; интерфейс лишь прячет ненужные кнопки. Начальник цеха и ОТК получают уже отфильтрованные данные — чужих данных нет даже в ответе API.
- Защита от CSRF (заголовок + проверка Origin), CSP с хэшами скриптов, заголовки безопасности, параметризованные SQL-запросы, журнал действий, защита от удаления/отключения последнего администратора.
- Страница панели **не содержит данных**: они приходят только после входа (проверяется тестом).

**Ограничения (честно):** по умолчанию сервер слушает `127.0.0.1` по HTTP; для доступа с других компьютеров его нужно поставить за HTTPS-прокси (nginx, Caddy) и включить `PROFIL_SECURE=1`. Проект учебный, сторонний аудит безопасности не проводился. Демо-пароли публичны — они в этом файле.

## Что есть на панели

| Лист | Что показывает |
|---|---|
| **Сводка** | Потери времени, доступность станков, брак, потери в деньгах; автоматические выводы «что видно по данным» с советом «что делать»; два ключевых графика |
| **Простои** | Тепловая карта «станок × день» (с выбором причины), Парето причин, простои по станкам и причинам, день/ночь по станкам, плановое ТО отдельно |
| **Брак** | Динамика по дням и сменам, брак по операциям, недельная динамика «день / ночь» по каждой операции, типы дефектов |
| **Данные** | Обе исходные таблицы с поиском и сортировкой по клику на заголовок; над таблицей — итоги по видимым строкам, чтобы любую цифру проверить вручную |

## Обязательные функции

- **Загрузка данных по кнопке.** «Загрузить данные» (справа вверху) принимает файлы CSV и XLSX — можно выбрать сразу оба. Панель сама определяет, где простои, а где брак, читает кодировки UTF-8 и Windows-1251, разделители `;` `,` и табуляцию, даты `ГГГГ-ММ-ДД` и `ДД.ММ.ГГГГ`. Строки с ошибками пропускаются и перечисляются в отчёте под шапкой; если журналы охватывают разные периоды или файл пустой, панель предупреждает. «Вернуть исходные данные» возвращает встроенные журналы.
- **Скачать PDF на каждом листе.** Кнопка сохраняет именно открытый лист (в светлой теме для печати, с разбивкой на страницы A4 по границам блоков и подписью «лист · фильтры · страница»; допущения по ставкам раскрыты).
- **Фильтры**, влияющие на все графики и цифры: период (даты или быстрые кнопки «Нед. 1–4»), смена, цех. В журнале брака нет цеха, поэтому фильтр по цеху действует только на простои — это отмечено на панели.
- **Тёмная и светлая тема** (кнопка в шапке; по умолчанию — как в системе).

## Допущения (важно)

В исходных журналах нет объёма выпуска и денег. Поэтому:

- **«Выработка» = доступность оборудования**: фонд времени (станки × дни × смены × длительность смены) минус потери и плановое ТО;
- **рубли** считаются по ставкам, которые можно менять в блоке «Допущения для расчёта времени и денег» на Сводке. По умолчанию: смена 8 ч, станко-час простоя 3 000 ₽, бракованная деталь 1 500 ₽. **Это оценка, а не бухгалтерские данные.**

## Экран без прокрутки

На мониторе от 1280×700 (ориентир — 1920×1080) каждый лист целиком помещается в окно: сетка карточек занимает всю высоту, высоту графиков вычисляет сама карточка, длинные таблицы листаются по страницам. На меньших окнах и телефонах панель переходит на обычную прокрутку. В карточках — крупные значения, минимум мелкого текста, выводы в форме «заголовок → деталь → что делать».

## Как проверить, что цифры не выдуманы

Контрольные цифры исходных данных: 120 записей простоев на 6 960 мин (из них 5 635 мин — внеплановые потери = 93,9 ч), 94 записи брака на 218 шт.

Автоматическая сверка — `tools/verify-panel.cjs`: скрипт независимо разбирает исходные файлы и сверяет их с панелью по 54 комбинациям фильтров (1 089 проверок: KPI, суммы всех графиков, тепловая карта, лист «Данные»). Запуск: `node tools/verify-panel.cjs` (автономная панель) и `node tools/verify-panel.cjs --server` (то же для серверной версии: сервер поднимается сам, вход директором). Нужны Node.js и Microsoft Edge (Windows). Последний прогон обоих: **54 комбинации, 1 089 проверок, 0 расхождений**.

Другие проверки версии 3: `node tools/test-server.js` — 35 тестов сервера (права каждой роли, блокировки, сессии, утечки данных и хэшей); `node tools/e2e.js` — 32 проверки в настоящем браузере (вход, роли, добавление записей, смена пароля, выход). Чтобы убедиться, что тесты способны падать, в код нарочно ломались проверка владельца записи и фильтр по цеху — упало 4 теста. Чтобы убедиться, что сама сверка способна что-то найти, в панель нарочно вносилась ошибка (фильтр смены для брака) — сверка показала 324 расхождения.

## Как собрать панель из исходников (для разработчика)

Исходники — в папке `app/` (React 19 + TypeScript + Vite + Tailwind 4). Нужен Node.js 22.18+.

```bash
cd app
npm install
npm run build      # app/dist/index.html (автономная; копируют в panel/index.html) и ../server/public/index.html (для сервера)
npm run dev        # режим разработки
```

## Технологии

- **VOLT** — дизайн-система (токены, компоненты, тёмная и светлая темы), шрифты Unbounded, Golos Text, JetBrains Mono вшиты в сборку.
- **Bklit UI** (MIT) — графики: столбцы, стопки, группы, линии; код скопирован в проект через shadcn registry.
- **motion** — переходы между листами, скользящие переключатели, появление блоков и уведомлений; **anime.js** — счётчики показателей и волна тепловой карты. При включённой в системе настройке «уменьшить движение» перемещения отключаются.
- SheetJS — чтение XLSX; html-to-image и jsPDF — экспорт в PDF.
